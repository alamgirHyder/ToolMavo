# Deploy ToolMavo on Hostinger Node.js hosting

This package uses **Vue + Express + MySQL**, matching the Node.js feature shown in your hosting plan. It does not need Java, PostgreSQL, a VPS, or a second hosting provider. MySQL availability and the exact Node.js controls must still be confirmed in your hPanel.

## 1. Create the website

In hPanel, open **Websites → Add website** and choose the **Node.js app** option. Do not choose WordPress or a static-only site. Use your included first-year domain if still eligible, or a temporary domain if offered. Review renewal prices for any claimed domain. If the panel does not offer a temporary domain, use an existing domain/subdomain or ask Hostinger support which testing address your plan supports.

## 2. Create the database

Open the website's **Databases → MySQL Databases** area. Create a new database, database user and strong password, and assign the user access to that database. Copy the **full database and user names**, including any account prefix. Use the database hostname shown by Hostinger; do not assume it is localhost. Keep the password in the hPanel environment-variable settings, never in Git or screenshots.

## 3. Upload or connect the application

Two supported source options:

- Connect the GitHub repository `alamgirHyder/ToolMavo` and select the branch containing this Node.js implementation.
- Upload `artifacts/toolmavo-hostinger.zip`, generated by `npm run package:hostinger`, using Hostinger's Node.js upload flow if available.

The application root must be the folder containing the **root `package.json` and `server/`**. Do not set the application root to `frontend` or upload only `frontend/dist`: invoices and contact submissions require the Express server.

## 4. Configure the Node app

| Setting                            | Value                              |
| ---------------------------------- | ---------------------------------- |
| Framework                          | Express / custom Node.js app       |
| Node.js                            | 24, or 22.12+ if 24 is unavailable |
| Application root                   | Repository/package root            |
| Install command, if requested      | `npm ci`                           |
| Build command                      | `npm run build`                    |
| Start command, if requested        | `npm start`                        |
| Startup file, if requested instead | `server/index.js`                  |
| Environment                        | Production                         |

Express serves static files from `frontend/dist`; it is not a static-only deployment. If Hostinger asks for an output directory, use `frontend/dist` only for the static-assets field, while retaining the Node server entry. Hostinger normally supplies the listening `PORT`; do not force it to 8080 in production unless the panel specifically requires that.

## 5. Environment variables

Enter these in the Node.js application's environment-variable panel:

| Name          | Value                                            |
| ------------- | ------------------------------------------------ |
| `NODE_ENV`    | `production`                                     |
| `DB_HOST`     | Hostinger's displayed MySQL hostname             |
| `DB_PORT`     | Hostinger's displayed MySQL port, usually `3306` |
| `DB_NAME`     | Full database name                               |
| `DB_USER`     | Full database user                               |
| `DB_PASSWORD` | Your database password, entered securely         |

`DB_SSL=true` is optional for a remote database requiring TLS. Certificate verification stays enabled. Leave `TRUST_PROXY_HOPS` unset initially; ask Hostinger support how many trusted reverse-proxy hops precede the app before setting it. An incorrect setting can let users bypass per-IP limits or group visitors behind one limit.

## 6. Deploy and verify

Deploy/restart the Node.js app and inspect its logs. Successful startup prints `ToolMavo is listening. Database: MySQL.` The app creates its two tables automatically if the database user has CREATE permission.

On your assigned HTTPS domain:

1. Open `/api/health`; expect `{"status":"UP","database":"MySQL"}`.
2. Open the home page and search for a tool.
3. Resize an image and download the result; merge two PDFs.
4. Save a test invoice and submit a contact message.
5. In phpMyAdmin, confirm the `invoice` and `contact_message` tables contain your test records.

If startup fails, check database hostname, account prefixes, password and privileges in hPanel. A 502 usually means the Node process failed or the start/root/port configuration is incorrect. Use the log error code; do not share credentials. An HTTP 429 means the submission limit was reached; wait 15 minutes and verify proxy configuration if multiple visitors are affected.

## Operational limits

Contact messages are stored, not emailed. Invoice saves create new receipts, not an editable account dashboard. Keep regular database backups and add reviewed legal/operator information before public launch. No live Hostinger deployment is claimed until the application's actual public URL has been tested.
